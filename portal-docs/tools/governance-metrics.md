# Governance Metrics

Governance Metrics is a browser for the Overview dashboard's own KPI tiles — but as real, first-class Egeria elements you can inspect and click into, not just numbers on a card. Every tile on Egeria Overview is backed by a real `GovernanceMetric` element (Egeria model 0450), linked via a real `GovernanceResults` relationship to the `Report` that actually computes it.

Access it from the portal tile (🎯 Governance Metrics) or directly at `/governance-metrics`.

---

## The metric list

Each card is one `GovernanceMetric`. This is deliberately **Tier 1** of a larger lineage design: it shows the metric and the Report that computes it, but doesn't yet trace lineage further back into the analytic function or its underlying data source — those aren't Egeria elements yet.

---

## Metric detail

Selecting a metric shows:
- Its own properties as an Egeria element.
- The linked **Report** — the Report Spec (FormatSet) that actually computes the value, with a **run it live** action that executes it on demand, the same execution path as the `View Report` Dr.Egeria command uses elsewhere in the Portal.
- The metric's **data flow** — a per-metric `InformationSupplyChain` element (named `"<metric name> Data Flow"` by convention) whose Purposes/Scope text and member list document, in prose, what actually feeds the calculation. This is a *documented* flow, not a queried one — Egeria doesn't yet have the DataFlow lineage relationships needed to compute it automatically.

---

## Where this data comes from

Every `GovernanceMetric` here is generated by a script (`gen_governance_metrics.py`) into a single Dr.Egeria document, which is itself one of the [Data Initialization](data-initialization.md) batches that reseeds automatically if Egeria's metadata store is wiped. **Manually re-running that batch from the admin panel is flagged unsafe** — it links each metric's `GovernanceResults` relationship with no check for whether it already exists, so a manual re-run against already-seeded data duplicates the relationship. Auto-heal is unaffected (it only ever runs when the data is confirmed missing); see [Data Initialization](data-initialization.md#confirmation-on-risky-re-runs) for what the confirmation prompt means if you see it.
