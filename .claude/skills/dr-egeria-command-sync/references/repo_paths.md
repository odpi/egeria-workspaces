## Staleness observed (2026-07-02)

The old `egeria-workspaces` (non-`-fs`) checkout's template copy had last
been touched 2025-12-09 and was missing entire families that existed
upstream (Actor Manager, Collections, Projects, Report) — about 6 months of
drift, 84 files vs. 157 in the source, plus renamed folders ("Feedback
Manager" vs source "Feedback") and a stray "General" folder with no source
counterpart. That checkout turned out to be the wrong sync target entirely —
`egeria-workspaces-fs` is the one the running Portal app actually reads, and
its copy was current (163 files) as of the same date. This history is kept
here as a reminder of why the sync always mirrors (`rsync --delete`) rather
than copying additively, and why it's worth confirming which local checkout
is "live" before assuming a path is still correct.

## pyegeria version propagation (not automated by this skill)

`trellis/packages/egeria-advisor`'s `pyproject.toml` pins
`pyegeria>=6.0.17.5` (as of 2026-08-09) and installs it like any other PyPI
dependency — it is not a local/editable checkout of egeria-python. This
means changes to `pyegeria/view/base_report_formats.py` (report specs)
only reach it when someone bumps the pyegeria version constraint and
reinstalls/reruns `uv sync` (or equivalent) in that package — this skill
does not publish or bump pyegeria versions. If a command change affects
report specs and the user needs that live in trellis/egeria-advisor,
flag it as a separate follow-up rather than assuming the template/help sync
covers it.
